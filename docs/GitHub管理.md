## 后续开发

开始修改前执行 `git status --short --branch` 与 `git pull --ff-only`，从最新 `main` 建功能分支。按任务修改源码与相关文档，运行对应回归；涉及打包、Tcl 或 Capture 行为时按照项目交接文档补充冻结程序与原生验证。

提交前检查 `git diff`、暂存清单和测试结果，提交时说明问题、改动与验证。功能分支推送后通过 Pull Request 审阅；合入后保持 `main` 为可复现的稳定代码。不要把用户工程、运行队列、配置或凭据提交到仓库。
