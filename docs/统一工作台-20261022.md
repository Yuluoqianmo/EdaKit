# EdaKit 统一工作台

三个原有菜单入口保留，统一打开一个原生 CEF 面板：`EdaKit Workbench`。顶部始终显示“器件商城｜器件属性｜BOM”，当前标签有蓝色下划线和选中状态。从 Capture 菜单进入任一功能时，激活对应标签。

每个功能首次使用才加载，之后保留其页面实例。标签切换只改变可见页面，不重载页面或刷新工程数据；商城浏览状态、属性编辑草稿、BOM 填写内容和表格滚动位置保留。关闭／重开原生工作台沿用已验证的 CEF ShowWidget 生命周期，不额外新建三个面板。属性与 BOM 的持久草稿继续沿用各自既有机制，程序退出后的恢复范围不变。

原生菜单用原子写入的会话导航文件通知工作台，URL 始终是 `/workbench?session=...`，避免通过修改 URL 或重新 LoadResource 来切换功能。壳页面按会话读取导航修订，菜单变化时选中标签；用户点击标签不会被未变化的旧菜单状态覆盖。导航文件只允许固定功能名和范围，会话路径受校验，不执行文件内容。

菜单入口：

- `EdaKit → LCSC Mall`：器件商城。
- `EdaKit → Component Properties`：器件属性。
- `EdaKit → BOM Preview`：BOM。

采用 ES5、XMLHttpRequest 和普通 iframe，兼容本机旧 CEF。内部直接页面路径仍保留以支持诊断与已有测试。商场 CEF 不可用时的旧查看器回退继续保留。

本次包含原生 Tcl 入口变化，更新后需保存工程、完整退出并重新启动 Capture，使旧的独立面板退出，加载统一入口。不在用户运行中的 Capture 内动态重新 source 插件。

验证包括：三个菜单连续五轮只创建／加载一个原生面板；导航隔离与非法路径检查；浏览器验证菜单切换、首次按需加载、三个页面各保留一个实例且仅一个可见、属性草稿和 BOM 输入保留、商城页面实例保留，以及桌面／窄窗口。商城网络以隔离接口数据测试；原生真实显示与操作仍需用户更新后验收。最终回归及部署记录见项目交接。本轮不提交或推送 Git。
