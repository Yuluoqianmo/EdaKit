# 封装库命名规范 v1

| 对象 | 格式 |
| --- | --- |
| Capture 内部零件名 | `EK_<CID>_S_<符号摘要前8位>_P9` |
| PCB 库名 / PCB Footprint | `EK_<CID>_F_<几何摘要前10位>` |
| Padstack | `EK_<焊盘摘要前20位>` |
| 累积原理图库 | `<设置的原理图库目录>/EdaKit.olb` |

内部名仅含 ASCII 字母、数字、下划线且不超过 31 字符。CID 为 C 加最多 11 位数字，非标准 CID 使用有界摘要标识。扩展名不属于库名。不同器件可复用相同焊盘定义。

PCB SHA256 输入包含完整解析后封装数据、生成格式版本、位号前缀；符号摘要包含完整符号数据、Capture 格式版本和 PCB 摘要。相同输入同名，几何或引脚变化产生新名；注册表保留完整摘要和文件哈希。

Capture 的 `PCB Footprint`、`PCBFootprint` 与 Allegro 库名来自同一函数。厂家型号仍保存在 `Manufacturer_PN` 和 PartValue，原始封装名保留在配对清单/注册表。PCB 位号使用原理图前缀 R/C/L/U 等。

不得重新编号。生成前验证原理图与 PCB 物理编号集合、数量及重复情况，构建后读取 Allegro 原生引脚编号和坐标。非 Power 重复功能名继续按已有规则消歧，Power 类型依据源属性。PCB 源数据未提供独立功能名，不能将编号校验宣称为独立功能名验证。

生成行为或几何规则改变时更新格式身份，避免复用旧缓存。用户文件不自动覆盖，旧实例通过重新放置显式升级。
