# 重复放置复用优化

**后续修正：** [电容符号与连续放置修复](电容符号与连续放置修复.md)已替代本文的单一固定放置库方案，改为内容独立的稳定路径及文件名。本文356项测试及散列仅代表当时阶段；当前366 passed / 1 skipped，原生Capture验收待确认。


日期：2026-10-21。目标：同一器件再次放置时复用已经生成并验证的 Capture 库，缺失、变化或损坏时恢复原生成流程。

## 原因与实现

商城的 Capture 专用准备原本已经跳过 PCB 封装 SKILL 和 STEP 下载。实际重复工作是符号 XML 生成、工程 OLB 合并、放置 OLB 写入和 Capture 往返规范化。其中每次启动合并 exe、执行原生转换更影响体感。

新增两层复用：

1. Python 用符号内容、内部零件名、封装名、目标库路径、DefaultValues 校准模板和转换格式版本生成输入指纹。Capture 专用 XML 采用稳定的指纹路径，并验证文件 SHA256；命中时直接返回原文件，避免重新生成时间戳导致内容一直变化。完整 stage/build 导出路线保持原语义。
2. 请求携带 XML 的 SHA256。Tcl 仅缓存已经规范化且正向回读确认包含目标 Package 的 OLB；每个缓存保留源 XML、已验证 OLB 快照及完成标记。复用前精确比较源 XML 和二进制库内容，不仅判断同名、修改时间或文件大小。命中后跳过工程库合并、合并 exe 启动及所有 XML/OLB 转换，直接使用有效库。

按器件内容保存缓存，所以 A→A、A→B→A 和重启后都可命中。放置入口继续使用一个 lcsc_test.olb；切换器件时复制已验证库并更新修改时间，保持原来的 Place Part 面板入口。缓存本身的路径不交给 Capture。规范化库缓存最多保留 128 项。

放置等待切回原理图时，其他 Capture 可能切换固定库；恢复等待任务前会在跨进程库锁内重新确认并恢复对应器件，再启动放置。

已有项目 OLB 只有“同名器件”不足以证明与当前 CAD 内容一致。因此升级后的首次使用会正常生成一次，建立已验证缓存；此后才复用。工程库缺失、输入内容/校准模板/目标路径变化、缓存文件缺失或被修改均回退生成。回读失败的库不记为可复用。远端 CAD 变化须先被现有取数/组件缓存感知，不宣称实时监测远端修改。

## 验证

- 完整回归：356 passed / 1 skipped（缺 lxml 的 XSD 检查）；17 个新增专项测试实例。
- Python：重复实例复用且不重写文件；符号、封装名、目标库、模板、格式版本变化及 XML 损坏/删除时失效。
- Cadence tclsh 实际执行：A→A、A→B→A、活动库删除后恢复、同大小二进制损坏、源 XML 改动、工程库删除、回读失败不缓存、独立进程重启后复用、等待任务期间切换库后恢复。
- Tcl 测试确认缓存命中时转换与合并调用计数为 0，而失效时计数恢复；测试使用原生命令桩，不等同于 Capture C++ API 真机验证。
- 冻结包 11 项自检通过，GUI/CLI 子系统正确；联调覆盖真实搜索、CAD、PNG、ETag、两次独立请求的稳定 XML 路径和一致 symbol_digest。
- 冻结包一次联调中 C13755 的准备阶段为首次 62.19ms、再次 5.34ms。这是 Python 准备阶段，未包含网络首次取数、队列轮询、Capture 原生转换及最终用户落点；不能据此承诺整体提速比例。

完整/专用产物比较测试改为比较除生成时间戳外的全部 XML 结构，消除跨秒引起的原有偶发失败；未放宽几何、属性或零件名检查。

临时脚本和证据位于 E:\outputs\.edakit-ui-qa：placement-reuse-frozen-qa.py、placement-reuse-frozen-final-qa.py、placement-reuse-selftest.txt、reuse-tests-*；构建包位于 dist/placement-reuse。

- 用户配置和已有工程库路径保留；缓存写在现有 staging 和 %LOCALAPPDATA%\edakit\olb_cache 下。

## 生效与真机补验

程序和 Tcl 必须同步更新，并退出全部 Capture 后重新打开。

首次放置 A 应正常生成；Esc 结束放置后再次点击 A，应出现 HIT 并更快启动光标。再放置 B、返回 A，检查符号、引脚和属性正确；关闭重开 Capture 后再次放置 A。若同时使用两个 Capture，还应检查一个实例等待原理图时另一个实例切换器件，恢复后仍放置正确器件。

尤其需要在真实 Capture 上确认“从缓存恢复固定库”能正常触发宿主库刷新；当前证据是字节一致性、原生命令桩及冻结包 API 验证，没有将它写成已经完成真机验收。

回退：dist/rollback-before-placement-reuse 保存更新前 GUI、CLI、已安装 Tcl、入口及配置副本。先退出全部 Capture，恢复两个 exe，再用恢复后的 CLI deploy 同步 Tcl。无需删除现有库和配置。
