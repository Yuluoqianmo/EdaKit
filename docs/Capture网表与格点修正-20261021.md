## P5R2 放置入口纠正

规范化后用户再次通过 Place Part 面板放置，仍有引脚分离。对照历史交接与当前插件，面板路径已有同类失败记录；已验证的插件路径为激活原理图、UnSelectAll、ZoomRedraw、PlaceNew。前两轮指导使用面板遗漏了此条件，不能据此断言 P5 几何错误或规范化足以解决面板兼容性。

现保留同一份 P5R2 最终 OLB，新增 `capture-p5r2/place_native.tcl`，为每次放置创建独立库路径快照，并调用现有插件相同的原生放置序列。用户先按 Esc 退出面板放置，删除测试页旧错误实例，激活原理图后 source 此脚本，点击落位。此为区分入口影响的原生复测，尚待用户确认；Tcl 模拟测试仅验证调用顺序和参数，不代表实际图形通过。

## 当前修订：P5R2 手动转库链路

初版 P5 手动脚本只执行 XML→OLB→回读 XML，遗漏插件已验证必需的回读 XML→OLB 规范化写回步骤。用户放置后再次出现引脚与本体分离。对比初版输入和回读 XML，57 个引脚的 position、hotpoint、start、名称、电气类型一致，因此不能仅靠 XML 坐标一致判定放置正常。

当前改用 `E:/outputs/edakit-pcb-import-20261021/capture-p5r2/build_library.tcl`：输入 XML→中间 OLB→Capture 规范化 XML→独立最终 OLB→最终回读。最终库为 `C2040_P5R2.olb`，零件名 `RP2040_P5R2`，避免已加载旧库缓存。该修订保留 P5 的唯一名称和 100 mil 格点逻辑；相关回归 33 项通过，真实放置仍需用户验证。通用 `generate_capture_run_tcl` 也补齐规范化步骤。旧 P5 测试文件保留作证据，下文初版操作路径不再用于新测试。

用户导出 C2040 网表时，PSTWRITER 17.2 报 ORCAP-36041：IOVDD、DVDD 引脚名称重复；并发现连接点无法匹配默认格点。

源数据将 IOVDD、DVDD、GND 等标为 bidirectional。现保留源电气类型，不依据名称推断 Power；对非 Power 的重复名称按物理编号顺序追加序号，并避开已有名称（例如已有 NC1 时继续寻找可用序号）。明确标为 Power 的引脚保持同名。原始数据、物理编号和 PCB 封装不变；pinmap 另记 capture_name 与 capture_electrical_type，保留源名称。

Capture 输出使用模型副本，将连接点对齐 100 mil（10 个库单位），同侧相邻连接点至少保留一个格点间隔。沿引脚方向向外对齐，调整长度保持本体端所在边；同步生成名字和编号标签。保留本体图形，非正交引脚当前明确拒绝。该策略针对常用 100 mil pin-to-pin spacing；用户自定义的页面格点还需匹配其工程设置。

源码缓存格式与零件版本已提升为 P5。已安装可执行文件尚未重新打包，插件仍可能生成旧 P4；本轮使用独立 XML 手动转库验证。

## 人工操作

在 Capture 命令窗口运行：

```tcl
source "E:/outputs/edakit-pcb-import-20261021/capture-p5/build_library.tcl"
```

预期打印 EDAKIT_P5_LIBRARY_READY，生成 C2040_P5.olb 及 roundtrip XML。如 XMATIC 命令不可用，保留消息后反馈，不继续放置。

在独立测试工程删除旧 U1 和此次为它创建的测试导线，通过 Place → Part → Add Library 加入该 OLB，选择 RP2040_P5 放置到格点。不要继续从旧插件放置 P4。检查 PCB Footprint=C2040_QFN56_EP，位号 U1。重新连接 TEST_PIN1 与 TEST_EP57 后，按照前一轮 PCB Editor 网表设置导出、创建或更新测试板。查看 Session Log 和板内 U1 的连接关系。
