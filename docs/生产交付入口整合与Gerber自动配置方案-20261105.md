# 生产交付入口整合、Gerber 自动配置与界面原型

日期：2026-11-05。当前阶段为方案分析和原型选择，不修改正式插件、安装包或 Allegro 启动配置。

## 1. 现有实现与入口整合

现有菜单同时注册 `Interactive BOM...` 与 `Production Delivery...`。生产交付已经支持 Gerber、器件坐标、加工说明、iBOM 四类独立勾选输出，后端复用了 `exporter.generate()`。

因此可以整合，但需迁移独立窗口的完整设置，不能仅删除菜单：

| 功能 | 当前情况 | 建议 |
| --- | --- | --- |
| iBOM 输出 | 交付窗口已支持 | 保留为可独立勾选输出 |
| PCB 属性 / 最终 BOM | 独立窗口支持；交付后端固定 `use_board=True` | 交付内新增 iBOM 设置页，显式传递数据来源与 BOM 路径 |
| 已保存最终 BOM | `bomByBoard` 按 PCB 路径保存 | 读取现有映射，不丢失用户资料 |
| 完成后打开 | 独立窗口提供 | 合并为 iBOM 专用勾选项 |
| 输出目录 | 独立 iBOM 与交付目录目前不同 | 交付使用底部统一目录，所有本次输出均归入该目录；原 iBOM 路径配置保留兼容，不直接覆盖 |
| 原命令 | 有 `edakit_ibom` 等已注册命令 | 保留旧命令作为兼容入口，打开统一窗口并只勾选 iBOM |

建议菜单只保留 `Production Delivery...`；统一窗口提供“仅导出 iBOM”快捷操作。是否删除独立菜单项在实施时按用户最终选择执行。

仅导出 iBOM 时，不要求 Gerber 参数或加工说明必填项。只有勾选的输出项目参与前置校验；iBOM 使用最终 BOM 时须检查位号匹配、重复位号和未匹配器件，并明确显示来源。

## 2. Gerber 当前缺少什么

`delivery.run()` 当前会查找工程已保存的 `art_param.txt` 和 `nc_param.txt`，使用 PCB 副本运行 `artwork.exe`、`nctape.exe`、`ncroute.exe`，并检查日志和产物。它会读取现有 Film 清单，但不会按 PCB 创建 Film。因此“能导出 Gerber”与“能一键设置每个 Gerber 文件的层”是两个阶段。

用户截图可以参考的部分是：可查看每个 Film 包含的 Class/Subclass，一键建立常用层组合，再统一输出。截图本身不能证明对方插件采用了哪一种内部实现。

## 3. 建议的数据与生成流程

1. 获取当前 PCB 快照及只读元数据：实际铜层顺序和名称、层类型及极性、各 Class/Subclass 是否存在和有无图形、已有 Film、板框候选、孔及槽的跨层信息。
2. 生成结构化的本次制造配置，记录每个 Film 的文件名、完整层列表、极性、镜像、偏移及配置来源。原型中的 INNER1 等名称是示例；正式代码必须采用工程实际名称与顺序。
3. 显示“建议层映射”。一键配置仅处理可明确识别的内容，多候选板框、负片平面或特殊叠层列为待核对，不把识别失败当成成功。
4. 在可验证的副本执行环境中使用 Allegro 原生 Film API 应用配置，保存加工副本，再调用现有导出链。
5. 核对日志、Film 清单、输出完整性、单位和坐标原点；全部完成后发布到选择的输出目录。

用户可在“按 PCB 自动配置”与“使用工程已有配置”间选择。自动模式不覆盖源 PCB；如以后提供“保存到当前工程”，须作为另一个明确操作。

## 4. 常规板的默认映射

| 文件角色 | 建议层来源 | 处理原则 |
| --- | --- | --- |
| 板框 | 已确认的 OUTLINE 或 DESIGN_OUTLINE，加必要的 CUTOUT | 切口作为板框补充，不单独当作完整外轮廓；多轮廓需核对 |
| 顶层 / 底层 / 各内层铜 | 实际铜层对应的 ETCH、PIN、VIA | 按叠层顺序生成，不用名称排序猜层序；不一律设正片 |
| 顶底阻焊 | 实际存在的 PIN、VIA、PACKAGE GEOMETRY、BOARD GEOMETRY 阻焊子层 | 按 padstack 和工程几何输出；加工说明中的盖油文字不能替代阻焊图形 |
| 顶底丝印 | 实际存在的 BOARD GEOMETRY、PACKAGE GEOMETRY、REF DES 丝印子层 | 位号、封装丝印分别可选，不默认混入装配图和元件值 |
| 顶底锡膏 | PIN、PACKAGE GEOMETRY 及工程存在的其他有效锡膏子层 | 空面不默认当作双面有开口 |
| 钻孔 | NC Drill 设置和实际孔跨层 | 钻孔是独立 NC 文件，不是加入铜层 Film 的“孔层”；PTH/NPTH 与盲埋孔分组需验证 |
| 槽铣 | NC Route 数据与实际槽型 | 与钻孔分开处理；板框线不自动等同于所有槽铣轨迹 |

常规方案可推荐独立板框 Film；是否同时叠加到其他 Film 留给明确的配置选项。默认线宽、精度、单位和格式须来自当前工程或经验证的制造配置，不照抄截图的“5”。底层不因为位于 Bottom 就统一镜像。负片平面的反焊盘、热焊盘及边界需独立验收。

第一阶段建议支持常规刚性通孔 2/4/6 层板；HDI、盲埋孔、背钻、多叠层和刚柔结合先使用已有配置，直到相应输出流程验证完成。

## 5. 可行性依据与必须先验证的执行方式

本机 17.2 官方文档确认：

- `axlFilmCreate()` 可以新建或替换 Film，并指定 `?layers`、极性、镜像、偏移等。`axlGetParam("artwork")` 及 `axlGetParam("artwork:<name>")` 可读取现有 Film。
- `artwork` 批处理要求事先存在 Film 控制记录并保存布局；单写 `art_param.txt` 不能替代生成 Film。
- `allegro -s <scriptfile> <filename>` 是有文档的脚本启动形式。但 17.2 启动文档把 `-nographic` 标为 UNIX only，不能直接把 UNIX 示例承诺为当前 Windows 无界面方案。

建议先做一个最小技术验证：在独立工作目录中，用 Windows 可支持的脚本/批处理执行方式对 PCB 副本创建一个 Film，保存后由 `artwork -l` 读回并输出测试文件。确认进程退出、许可证、用户环境隔离和错误回报，再扩大到完整层映射。已发现本机存在 `allegro_batch.exe`，但尚未验证其参数与适用范围，不能据文件名认定它能执行本方案。

本机另有 Cadence 的 WM_COPYDATA 示例，可向正在运行的 Allegro 发送命令；示例说明没有操作结果反馈，且窗口选择与会话状态需要处理。它不作为首选默认通道，也不能不加识别地向任意 Allegro 窗口发送修改命令。

若副本执行通道未验证通过，保留“使用工程已有配置”的现有导出方式，不以静默修改当前设计或自动重启 Allegro 代替。

本轮仅阅读文件和文档，未启动 Allegro 或向其发送命令。

## 6. UI 设计方向

三版都采用 Allegro 17.2 常见的灰色工作区、矩形按钮、分组框、紧凑行距和标准输入控件。减少大面积卡片、圆角胶囊、宽侧边栏和装饰性摘要。

| 原型 | 布局与交互 | 适用 |
| --- | --- | --- |
| 原生标签页 | 顶部五个功能标签；当前页完成设置；Gerber 左侧 Film、右侧层明细 | 推荐默认方案，接近原生工程工具对话框，切换直接 |
| 工程树与属性表 | 左侧项目分类树；右侧属性表与 Film 清单；输出清单常驻左下 | 适合层映射经常需要编辑、参数逐项核对的用户 |
| 紧凑输出面板 | 同一页面内折叠设置分组，右侧按需输出与交付清单 | 适合完成参数记忆后反复一键导出的场景 |

公共交互：底部输出目录可编辑；只导出选中内容；iBOM 可单独输出；FR-4 默认、TG 手填；钢网下拉与 0°/90°有效面积示意保留。

原型使用演示 PCB 数据。点击一键配置和生成按钮只演示状态，不生成制造文件。

原型验证：三组方案完成切页、2/4/6 层映射变化、手工 TG 保留、最终 BOM 来源切换、仅导出 iBOM、空选择禁用生成、钢网 90°旋转交互检查；1100/800/480/360 像素共 12 次宽度检查通过，未发现横向越界，浏览器脚本错误为零。已查看三组截图。验证使用独立无头 Edge，仅访问原型，没有访问 Allegro。记录在 `E:/outputs/edakit-native-prototype-qa/results.json`。

实施仍建议保留独立 Python 窗口，并使用 Windows 原生 ttk Notebook、Treeview、LabelFrame、Entry、Combobox；先测试 `winnative` / `vista` 等主题在目标系统的效果。不要仅为外观一致就把整个交付界面迁入 Allegro 进程。下一次正式实现以原生控件可达到的外观作基准，并核验 Windows 125%/150%/200% 缩放。
