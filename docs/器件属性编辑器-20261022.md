# Capture 器件属性编辑器（2026-10-22）

第二个功能：在 Capture 内嵌可配置的工程器件属性表，使用原生属性名称，例如 `Manufacturer`、`PCB Footprint`、`Part Number`。首版采用按钮同步。

## 使用

1. 保存工作并重启 Capture，打开工程。
2. EdaKit → **Component Properties** 进入整个工程表。菜单仅保留这一个属性入口，在页面内搜索器件，或切换“整个工程 / 当前选中器件 / 当前页面”。当前页或选择范围须先在对应原理图页选择器件，再进入工作台。
3. 在“字段设置”勾选原生属性，调整顺序和列宽；可新增字段，并保存、使用、删除字段模板。新增字段只有填写并同步到对应器件后才成为实际属性。
4. 默认按 Reference 自然升序排列（R2 在 R10 前）；点击任意字段表头切换升/降序，排序覆盖全部分页，粘贴按当前排序后的行顺序应用。多行内容自动换行、撑开行高，编辑和窗口尺寸变化时重新计算。单元格直接编辑；从 Excel 粘贴矩形区域，或勾选行后批量填写。黄色为草稿，Reference 与原生只读属性不能编辑。选择筛选结果覆盖该筛选的所有分页；每页显示 100 行。
5. 点击“同步到 Capture”。每个修改先核对快照原值，再写入、回读，结果逐项列出。成功后刷新原值，最后在 Capture 保存工程。
6. 外部修改产生冲突时保留草稿并标红，不覆盖外部值。先记录所需修改，点击“读取 / 刷新”后重新编辑。刷新、切换范围、撤销草稿都有丢弃确认。
7. “恢复上次同步值”把上一批成功项的原值恢复为草稿，再次同步才写入。新增属性恢复为空值，保留属性名；这是插件级值恢复，不承诺接入 Capture 的 Ctrl+Z。

多单元按同一父层级路径和已标注位号合并，修改展开到各个实际单元。选中或当前页范围会展开到同一封装的其他单元，包含跨页单元；不同层级的同位号器件保持独立；各单元原值、只读状态和写入结果分别检查。局部失败会逐项报告，不承诺整批原子回滚。合并单元值不同时显示提示，编辑后统一写入各单元。一次最多提交 2000 个原生单元格。

草稿按 Capture 会话身份保存在浏览器 localStorage 中，同一服务地址、同一 Capture 会话内关闭再打开可恢复，并兼容读取旧 sessionStorage 草稿。退出 Capture、服务地址改变、清理浏览器数据或存储空间不足不保证恢复；关闭不弹出可能阻塞旧 CEF 的 beforeunload 确认，也不自动重放未完成的写入。请及时同步并保存工程。Occurrence Path 内部标识列已从界面删除；内部实例身份仍用于准确同步，不需要用户编辑。

## 实现

- 独立 CEF 控制栏，商城与属性页分别持有窗口，避免切换商城时重载草稿。
- `src/edakit/install/templates/properties.tcl`：真实 occurrence 层级遍历、有效属性读取、只读识别、原值冲突检查、写入及回读；缓存原理图焦点下的选择，避免 CEF 获取焦点后丢失选择。缓存以工程身份约束，不跨工程使用。
- `src/edakit/bridge/properties.py`：会话隔离、请求校验、不可由前端伪造的原值、字段模板保存和回执解析。
- 独立 `%LOCALAPPDATA%/edakit/properties/` 队列，不占用原理图库合并锁；UUID 文件、独占 rename、120 秒请求期限、写入中断不自动重放。请求只处理数据，不执行页面输入的 Tcl。值编码兼容 Tcl 8.5 的 UTF-16/CESU-8，包括中文、换行、等号、引号、方括号、分号和补充平面字符。
- Capture 内存保留最近 20 次快照；过期需刷新。磁盘回执最长保留 7 天，超时或宿主退出后必须核查工程再重试。
- 布局保存在 `%LOCALAPPDATA%/edakit/properties-layout.json`，与器件参数数据分开。默认列 Reference / Value / PCB Footprint / Manufacturer / Part Number；名称不汉化。
- HTTP：`GET /properties`、`GET/POST /api/properties/layout`、`POST /api/properties/request`、`GET /api/properties/status`。属性更新使用 POST。
- 前端源码 `frontend/properties/`，由 `tools/build_web.py` 生成部署资源；Tcl 保持纯 ASCII。安装、手动副本、冻结自检均包含新增资源。

## 关闭后再次打开修复（2026-10-22）

用户确认：首次打开后的修改属性可正常同步到 Capture；关闭 CEF 后再次打开卡死。验收记录据此更新，保存重开和复杂层级未扩大为已通过。

日志显示再次打开会反复等待服务启动 45 秒。根因是 Tcl `serverAlive` 把 `return 1` 放在 `catch` 内：Tcl 把 return 当作返回码 2，导致正常 TCP 服务也始终被判为失效。`ensureServer` 随即删除仍有效的 url.txt，重复启动进程又因独占锁退出，从而等不到新地址。已将成功返回移到 catch 外，并用真实 Tcl TCP 监听器验证连续两次复用、地址文件保留、已关闭端口拒绝。

属性入口冷启动改为 after 异步等待，连续点击只启动一次，不再在 Capture UI 线程睡眠等待 45 秒。服务独占锁持有者每秒修复丢失或陈旧的 url.txt，写入短暂失败保留运行服务并重试。使用 Cadence 自带 Footprint Viewer 同样的 IsContolBarVisible / LoadResource(id,url,1) 模式：已隐藏的 CEF 页重新加载，已可见页面保留状态；失效句柄仍按所有权规则清理。

删除菜单及命令 `Selected Component Properties`，保留单一 `Component Properties`；页内范围和器件搜索继续可用。关闭改为保存草稿，不触发 beforeunload 模态确认；同一 Capture 会话、同一地址的新浏览器页能恢复草稿。
