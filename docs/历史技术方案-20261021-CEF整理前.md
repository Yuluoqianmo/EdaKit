# 立创元件库 → Cadence 一键放置工具 · 需求与技术方案

> 目标：复刻 B 站 `BV1s8Hj6VEKg` 那款插件的能力，并按后续补充的用法扩展成「在 OrCAD Capture 里内嵌一个立创商城」——搜料 → 看符号/封装/3D → 双击把符号摆到原理图上，PCB 封装与 3D 自动转换好放进库目录。最终交付一个 Windows exe，在你本机（Cadence 17.2 / 17.4 / 22.1）验证。
>
> 本文档是设计与实现说明，配套源码在本目录 `../`。凡未在你机器上实测过的判断，都标了「待实测」。

---

## 1. 需求总结

### 1.1 产品定位

一个寄生在 Cadence SPB 之上的辅助工具。它不替代 Capture/Allegro，而是把「去立创找料 → 翻格式 → 手搓库」这段重复劳动自动化。对用户而言只有两步：**在商城里挑料**，**点一下放到原理图**。背后分两个使用场景：原理图符号（Capture 侧）和 PCB 封装 + 3D（Allegro 侧）。

### 1.2 功能需求

**FR0 内嵌商城（界面主入口）**。在 Capture 里内嵌一个「立创商城」界面（独立浏览器窗口，由
Capture 菜单拉起 + 本地 HTTP 服务供数据）：

- 搜索：关键词（型号／厂家／描述／C 编号），并支持**按分类树浏览**（53 个一级分类，约 1200 个节点）。
- 结果列表：图、型号、厂家、封装、阶梯价、库存、分类路径、数据手册。
- 详情面板：分页签看**原理图符号预览、PCB 封装预览、3D 模型**、参数表；预览全部是本工具
  **按自己解析出的几何自绘的 SVG/three.js 模型**（立创的预览图端点已 403）。
- 放置：双击器件（或点「放置到原理图」）→ 符号进入 Capture 放置队列（默认跟随光标，点一下落位）；
  PCB 相关文件（SKILL 脚本、STEP、3D 映射）**同时自动生成并放进配置好的库目录**。

**FR1 取数**。给定立创 C 编号（如 `C2040`），从 EasyEDA 拉取该元件的符号、封装、3D 元数据。免鉴权端点：

```
元件数据   GET https://easyeda.com/api/products/{C}/components
3D STEP    GET https://modules.easyeda.com/qAxj6KHrDKw4blvCG8QJPs7Y/{uuid}
3D OBJ     GET https://modules.easyeda.com/3dmodel/{uuid}
```

商城的搜索／分类数据走另一组端点（**非官方、无文档、无鉴权**，从官网前端 JS 里读出来的），
详见 3.7。

**FR2 符号生成**。把 EasyEDA 符号（`shape` 数组，自有 canvas 指令集）转成 Capture 可用的 `.OLB` 库元件，尽量还原原外观（矩形、圆、弧、折线、多边形、文字、引脚），并写入属性（`Description`、`PCB Footprint` 等）。

**FR3 一键放置**。在 Capture 当前原理图页把符号摆上去（`PlacePart`），并写入实例属性、绑定封装名。

**FR4 封装生成**。把 EasyEDA 封装（`docType=4`）转成 Allegro 的 padstack + 符号：`.pad`（或内嵌 padstack）、`.psm`、`.dra`，含焊盘、引脚、丝印、装配层、`PLACE_BOUND`。异形焊盘要生成 `.ssm` 形状符号。

**FR5 3D 绑定**。下载 STEP 模型放入 `steppath`，并生成映射数据（`.map` XML / 3D Mapper XML），把模型绑到封装并做位置校准。

**FR6 部署**。一个 exe 完成：把 Capture TCL 插件装进 `tclscripts` 的 autoload 目录、把 SKILL 脚本放进可调用的位置、**自动把封装库目录写进 Allegro 的 `padpath/psmpath/steppath/step_mapping_path`**。

**FR7 版本适配**。同一套安装包在 17.2 / 17.4 / 22.1 上都能用，运行时探测能力、自动降级。

**FR8 累积工程库**。所有放置过的符号累加进**一个工程 `.olb`**：每次放置先 `XMATIC_OLB2XML`
回读已有库，把新元件的 `<Part>` 并进去（同名替换，幂等），再 `XMATIC_XML2OLB` 写回。

### 1.3 非功能需求

只能在 Windows 上跑；半段功能（封装/3D）要求本机装完整 SPB 且**有可用的 Allegro 封装编辑器 license**；取数以外的转换全部本地完成；失败要报清楚、不许静默产出半成品库。

### 1.4 边界与约束（必须写死，否则会踩坑）

- `.OLB` 是**未公开二进制**，外部程序不能直接生成，必须由 Capture 自己经 TCL 接口生成。
- `.dra` / `.psm` 同样是**二进制数据库**，只能由 Allegro 经 SKILL 生成，没有「文本 → .dra」的官方通道。
- 立创**官方不提供** Cadence 格式导出。任何转换都是社区逆向的非官方端点，上游随时可能变。
- 元件数据的版权归嘉立创 EDA 所有，非开源许可。该工具只适合自用/内部；**再分发库文件前先看服务条款**。

**结论：这不是一个能独立运行的软件，而是一个「编排器 + 注入到目标软件里的脚本」。** exe 负责取数、解析、生成中间件，真正的写库动作发生在 Capture / Allegro 进程内。

## 2. 总体架构

### 2.1 为什么必然是三段式

三段是被格式逼出来的，不是设计偏好：

| 环节 | 为什么不能纯外部做 | 只能怎么做 |
|---|---|---|
| 写 `.OLB` | 二进制未公开 | 让 Capture 自己调 TCL 生成 |
| 写 `.dra/.psm/.pad` | 二进制数据库 | 让 Allegro 跑 SKILL 生成 |
| 取数 + 格式解析 + 中间件生成 | 与 Cadence 无关，可离线 | 外部 exe 做 |

所以架构是：**Python exe（商城界面 + 转换核心） + Capture TCL 插件 + Allegro SKILL 脚本**，
通过中间文件（JSON / XML / TCL / IL / map / step / 队列）交接。

### 2.2 组件图

```
┌───────────────────────────────────────────────────────────────────────┐
│ lcsc2cadence.exe  (Python / PyInstaller，用户机器上运行)                 │
│                                                                        │
│  ┌──────────────────┐   ┌──────────────────┐   ┌───────────────────┐  │
│  │ server/  本地HTTP │◄──│ catalog/ 商城API  │   │ pipeline.py 落盘    │  │
│  │ server/web/ 网页  │   │ 搜索/分类/联想    │──►│ 符号XML/SKILL/STEP  │  │
│  └────────┬─────────┘   └──────────────────┘   └─────────┬─────────┘  │
│           │ 双击「放置」                                    │            │
│           ▼                                              ▼            │
│  ┌──────────────────┐   ┌─────────────────────────────────────────┐   │
│  │ bridge/queue.py  │   │ symbol/ footprint/ threed/ render/       │   │
│  │ 写 req_<seq>.req  │   │ easyeda/  (解析 + 生成 + 预览)            │   │
│  └────────┬─────────┘   └─────────────────────────────────────────┘   │
│           │  deploy → 写进 Cadence 安装树 + 配 Allegro env             │
└───────────┼──────────────────────────────────────────┬────────────────┘
            │ 队列文件（key=value）                      │ 生成 & 就地执行
            ▼                                          ▼
┌───────────────────────────────┐      ┌──────────────────────────────┐
│ OrCAD Capture (TCL 插件)       │      │ Allegro (SKILL)               │
│ · 每 400ms 轮询 req_*.req      │      │ · axlDBCreatePadStack / Pin   │
│ · XMATIC_OLB2XML → 合并 →      │      │ · axlDBCreateLine/Circle/Shape│
│   XMATIC_XML2OLB → .OLB        │      │ · axlSaveDesign + CompileSymbol│
│ · PlacePart（跟随光标）        │      │ · 3D 映射 (.map / 3D Mapper)  │
│ · 写 resp_<seq>.resp           │      │                              │
│ · 菜单 RegisterAction          │      │                              │
└───────────────────────────────┘      └──────────────────────────────┘
```

**为什么商城是「独立进程 + 本地 HTTP」而不是嵌在 Capture 的 Tk 里**：Capture 的 Tcl/Tk 版本老旧、
没有现代 web 控件，内嵌浏览器不可行；而放置动作又必须发生在 Capture 进程内。所以拆成
「界面（exe 的另一个进程）」+「队列（文件）」+「执行（Capture 内的 TCL）」。

### 2.3 数据流（用户视角只有两步）

```
① 搜料（界面进程）
  关键词/分类 ──► catalog.MallClient ──► 立创商城 API
  ──► 结果列表 ──► 点开某器件 ──► fetch + parse
  ──► render/ 自绘符号 & 封装 SVG 预览 + 3D OBJ（three.js）

② 放置（双击 / 点按钮）
  pipeline.stage_component:
      staging/<cid>/<cid>.olb.xml      符号库 XML（给 Capture 的 XMATIC）
      <封装库>/<封装>.il               Allegro 建封装的 SKILL
      <封装库>/<封装>.step  + .map.xml + .3dmap.xml
      staging/<cid>/README.txt         人读小抄
  bridge.PlaceRequest.submit() → queue\req_<seq>.req

  Capture 侧（400ms 后）:
      XMATIC_OLB2XML 已有工程库 → base.xml
      exec exe olb-merge --base base.xml --part <cid>.olb.xml --out merged.xml
      XMATIC_XML2OLB merged.xml → 工程库.olb
      PlacePart …（跟随光标）
      → queue\resp_<seq>.resp → 界面轮询显示「已放置」

  Allegro 侧（用户在 Allegro 里 load 一次，或首次放置后自动提示）:
      load("...\<封装>.il") → 生成 .dra/.psm/.pad
```

## 3. 模块拆解

### 3.1 取数层 `lcsc2cadence/fetch.py`

- 带 `User-Agent` / `Referer` 的 `requests` 会话；重试 + 超时。
- 三个方法：`get_component(cid)`、`get_step(uuid)`、`get_obj(uuid)`。
- 校验顶层 `success` / `code`；把 HTTP 错误、空 `result`、缺符号/缺封装分别报成不同的异常，别让上层拿到半个对象。
- **不缓存到磁盘以外**（可选加 `--cache` 目录，避免反复打上游）。

### 3.2 EasyEDA 解析层 `lcsc2cadence/easyeda/`

这是全项目的正确性核心，也是最需要拿真实数据校准的地方。

- `units.py`：封装 `1 单位 = 10 mil = 0.254 mm`；符号按 `(ee-bbox)*10*0.0254 mm` 且 Y 取反。全部内部统一成 mm。
- `parse.py`：把 `~` / `^^` 分隔的 shape 字符串解析成带类型的几何对象。
  - 符号指令：`P`(引脚) `R`(矩形) `C`(圆) `E`(椭圆) `A`(弧) `PL`(折线) `PG`(多边形) `PT`(路径) `T`(文字)。
  - 封装指令：`PAD` `TRACK` `HOLE` `VIA` `CIRCLE` `ARC` `RECT` `TEXT` `SVGNODE` `SOLIDREGION`。
  - **每个指令的字段序是逆向出来的**，代码里逐条注释，`dump` 命令可打出来对照。
- `model.py`：`dataclass` 承载 `Symbol / Footprint / Pad / Primitive / Model3D`，解析器只负责填，生成器只负责读，两边解耦。

> 关键设计：解析层**不假设**自己字段序一定对。`parse` 输出带 `raw` 原文，`dump --diff` 能把「解析出的几何」和「原始 shape」并排打出来，方便你用真实元件校准。

### 3.3 符号 → Capture `lcsc2cadence/symbol/`

`.OLB` 二进制写不了，所以符号只能经 Capture 自己生成。给出两条后端，运行时探测后择优：

**后端 A（首选）— XMATIC XML 往返**

```
XMATIC_XML2OLB  <in.xml> <out.olb>
XMATIC_OLB2XML  <out.olb> <roundtrip.xml>
```

工作流：我们的生成器产 `in.xml` → Capture 转成 `.olb` → 回读校验。

**这里的头号未知数是 OLB XML 的确切 schema。** 与其拍脑袋猜，本工具用一个更稳的办法闭环——**schema 自发现**：

```
learn-schema 命令：
  让用户在 Capture 里手建一个「参考元件」并导出成 .olb
  → 工具调 XMATIC_OLB2XML 把它转成 XML
  → 工具用 ElementTree 走一遍，产出**完整结构清单**：
      每个元素路径 / 属性名 / 取值样例 / 出现次数，以及文本内容
  → 这份清单就是权威 schema，据此把生成器的标签名改成真的
```

产物三份（都在 `--out` 目录）：`schema-report.txt`（人读，发回给开发方）、
`schema-structure.json`（机器可读）、`profile.json`（初次尝试的 profile，能直接喂 `--schema`，
但可能不全）。这样不依赖任何未公开文档，一次校准、长期可用。

> 说明：清单里报的是**去掉命名空间前缀**后的标签名；若原文带前缀（如 `ns0:Part`），
> 改生成器时要连 `xmlns` 声明一起补上。清单里也会如实反映「参考文件用了哪些标签」——
> 哪怕和 `DEFAULT_PROFILE` 里猜的完全不一样（那正是要拿它来纠正的地方）。

**后端 B（降级）— capCreatePartsFromData**

老版本无 XMATIC 时用。局限：脚本里没有矩形/线/弧的输入，只能「给引脚、由 Capture 生成方框本体」。即符号会退化成方框。代码里明确提示「当前为降级模式，符号外观不完整」。

放置与属性（两个后端通用）：

```tcl
PlacePart <X> <Y> "<库全路径，正斜杠>" "<PackageName>" "<子部件字母>" FALSE
# 属性：NewDisplayProp（库侧）/ SetEffectivePropStringValue（实例侧）
```

**Capture TCL 插件**（`install/templates/` 里的 `lcsc2cadenceInit.tcl` + `lcsc2cadence.tcl`）：

- `capAutoLoad/lcsc2cadence/lcsc2cadenceInit.tcl`：只负责定位并 `source` 主脚本（capAutoLoad 的加载
  时机足够早）。
- 主脚本 `namespace eval lcsc2cadence`：注册菜单（`RegisterAction`，三项：打开立创元件库 /
  能力探测 / 日志），**启动即开轮询**（`after 400`）。
- 轮询到 `req_<seq>.req` → `buildOlb`（OLB2XML → `exec exe olb-merge` → XML2OLB）→
  `placePart` → 写 `resp_<seq>.resp` → 删请求。
- 读队列用 `readKV`（`array set` + `foreach`，容错缺键用 `kvGet`），写结果用 `writeKV`。
- 全程 try/catch，失败把 `stage`（失败在哪个环节）写进 resp，日志可通过菜单查看，绝不静默。

### 3.4 封装 → Allegro `lcsc2cadence/footprint/`

`.dra/.psm` 二进制，只能让 Allegro 跑 SKILL。生成一份 `.il`，在 Allegro 里 `load("footprint.il")` 或 `axlShell` replay。

SKILL 建封装链路（函数名以官方 SKILL Reference 为准，注意几个常被写错的）：

| 步骤 | 函数 | 要点 |
|---|---|---|
| 开/建 .dra | `axlOpenDesign(?design "x.dra" ?mode "wf")` + `axlSetSymbolType("package")` | |
| 建 padstack | `axlDBCreatePadStack(t_name r_drill l_pad)` | 参数用 `make_axlPadStackDrill` / `make_axlPadStackPad` 构造；**没有** `axlPadstackCreate` |
| 放 pin | `axlDBCreatePin(t_padstack l_anchorPoint r_pinText [f_rotation])` | pinText **必须是 `axlPinText` defstruct**，不是字符串 |
| 丝印/装配 | `axlDBCreateLine` / `axlDBCreateCircle` / `axlDBCreateShape` / `axlDBCreateText` | 层名如 `"PACKAGE GEOMETRY/SILKSCREEN_TOP"` |
| place_bound | 同上的 create 函数，放到 `PACKAGE GEOMETRY/PLACE_BOUND_TOP` | 无专用 API |
| 存盘编译 | `axlSaveDesign(...)` + `axlCompileSymbol(?symbol ?type)` | `axlCompileSymbol` = create symbol |
| padstack 落盘 | `axlPadStackToDisk` / `axlDBCopyPadstack` | |

生成器 `skill.py` 把 `Footprint` 对象翻译成这些调用。难点（也是开源项目踩过的坑）已在代码里处理：

- **多层焊盘合并**：同编号跨顶/底/内层的焊盘要合并成一个 padstack（一层提供钻孔和默认铜形，顶/底各覆盖），**只生成一个引脚**。
- **异形焊盘**（圆角矩形、非圆椭圆、正多边形、自定义贝塞尔轮廓）→ 生成 `.ssm` 形状符号，曲线用折线逼近，误差 ≤ 0.002 mm。
- **硬限制**：Allegro 形状符号**不能有内部挖空**（25.1 也如此），遇到带内孔/多轮廓的铜焊盘要么报错退出，要么按参数决定是否填实——本工具默认**报错**，不静默丢几何。
- 阻焊 / 钢网开口暂用铜焊盘尺寸，热焊盘留给项目规则补。

### 3.5 3D → 映射 `lcsc2cadence/threed/`

- 从 `SVGNODE` 取 `uuid / c_origin / z / c_rotation / c_width`，按 `modules.easyeda.com/qAxj6KHrDKw4blvCG8QJPs7Y/{uuid}` 下 STEP。
- **位置校准**（这是「3D 自带位置校准」的真实含义，没有官方约定，各家自洽）：两种口径，代码都实现，由 `--calib` 选：
  - `easyeda2kicad` 口径：`tx=(c_ox-画布原点x)*0.254, ty=-(c_oy-画布原点y)*0.254, tz=z*0.254`；若外框中心与 (tx,ty) 偏差 > 0.1 mm 改用轮廓中心；`rx'=360-rx`。
  - `lcsc-library-converter` 口径：保留立创装配旋转，仅平移到封装原点 + 板顶安装面，不二次套用模型旋转。
- 绑定两条路：
  - **老机制** Step Package Mapping：生成 `.map`（**文本 XML**，放在 `step_mapping_path`），字段 `step_name / rotation_x·y·z / offset_x·y·z`；前提是符号含 `PLACE_BOUND_TOP/BOTTOM`。
  - **新机制** 3D Canvas / 3D Mapper（17.2 起）：生成 File-based Mapping XML 批量导入，或用 SKILL replay `pkgmap3d` 表单脚本。
- `mapping.py` 负责把两种口径 + 两种机制组合成正确的文件。

### 3.6 部署/安装 `lcsc2cadence/install/`

- `deploy.py`：定位 Cadence 安装根（注册表 / 环境变量 / 常见路径），把 TCL 模板拷进 `tools/capture/tclscripts/capAutoLoad/`，把 SKILL 放到约定目录，配置 `steppath` / `step_mapping_path`。
- `allegro_env.py`：把封装库目录写进**用户级** `%HOME%\pcbenv\env`（`padpath` / `psmpath` /
  `steppath` / `step_mapping_path`），用**带标记的块**包裹，幂等、可回滚、先备份，
  并且是 `var = <库> $var` 的**追加**写法，不动用户已有配置。不动全局 env。
- 安装包（Inno Setup）：装 exe + 首次运行自动 deploy，卸载可回滚。
- **不动用户已打开的工程**：转换走独立临时目录，写库另起进程。

### 3.7 商城数据 `lcsc2cadence/catalog/`

立创官网前端（`static.lcsc.com/feassets/pc/nuxt/*.js`）里读出来的四个端点，
**非官方、无文档、无鉴权**，2026-10-16 实测可用：

| 用途 | 端点 | 请求 | 响应用哪个字段 |
|---|---|---|---|
| 关键词搜索 | `POST /ftps/wm/product/query/list` | `{keyword,currentPage,pageSize}` | `result.dataList[]` / `totalRow` |
| 分类浏览 | `POST /ftps/wm/search/third/catalog` | `{currentPage,pageSize,wmCatalogIdList:[id]}` | `result.productList[]` / `totalCount` |
| 分类树 | `POST /ftps/wm/product/catalog/list` | `{parentId:0}` | `result.catalogList[]`（53 一级 / ~1208 节点） |
| 搜索联想 | `POST /ftps/wm/search/v3/global` | `{keyword}` | `exactMatchResult` / `catalogVOS` / `brandVOS` |

（`BASE = https://wmsc.lcsc.com`）

`MallClient` 要点：`currentPage`/`pageSize` **必填**；两个列表端点响应结构不同
（`dataList` vs `productList`），统一归一化成 `Part`；对 403/429/5xx 与非 JSON 响应做退避重试；
返回结构异常时抛「上游可能已变更」。

### 3.8 本地服务与网页界面 `lcsc2cadence/server/`

- 用标准库 `http.server`（`ThreadingHTTPServer`），**零额外依赖**，方便 PyInstaller 打包。
- 端点：`/`、`/static/*`、`/api/search`、`/api/browse`、`/api/categories`（缓存 1h）、
  `/api/part/<cid>`、`/api/svg/symbol|<footprint>/<cid>.svg`、`/api/obj/<uuid>`（3D 代理）、
  `/api/place`（POST）、`/api/place/status`、`/api/config`、`/api/status`、`/api/health`。
- 端口默认自动挑选（`bind(0)`），只监听 `127.0.0.1`。
- 前端（`server/web/`）三栏：分类树 | 结果表 | 详情（`符号 / 封装 / 3D / 参数` 四个页签）。
  3D 用打包进来的 `three.min.js`（MIT）+ 自研极简 OBJ 解析器，带拖拽/缩放/网格。
- **预览为什么自绘**：立创的 `/api/products/{C}/svgs` 端点当前返回 403（CloudFront）。自绘还有个
  额外好处 —— 预览图本身就是解析正确性的可视化验证。
- 静态资源目录按 `Path(__file__).parent / "web"` 定位，所以 spec 里必须把它打进包
  （见 `lcsc2cadence.spec` 的 `datas`）。

### 3.9 放置桥接 `lcsc2cadence/bridge/queue.py`

界面进程不能直接操作 Capture，只有 Capture 进程内的 TCL 能放置。所以走**文件队列**：

```
商城进程                      Capture TCL 插件
写 req_<seq>.req   ──►        每 400ms 扫队列目录
                              执行放置（XMATIC + PlacePart）
读 resp_<seq>.resp ◄──        写结果
心跳 heartbeat.txt            ts=<epoch> —— 界面据此显示「Capture 已连接」
```

**为什么是 key=value 文本而不是 JSON**：Capture 自带的 Tcl 不一定装了 tcllib 的 `json` 包；
`key=value` 一行一条，TCL 一个 `foreach` 就能读，零依赖。
**为什么是文件而不是 socket**：Capture 的 Tcl 不一定编译了 socket 扩展，而文件读写永远可用。
延迟 ~0.4s，人感觉不到。布尔值统一写 `1`/`0`（TCL 不认 `True`/`False`）。

### 3.10 落盘编排 `lcsc2cadence/pipeline.py`

一次「放置」需要落盘的全部文件，集中在这里，界面与命令行共用：

| 产物 | 去向 | 谁用 |
|---|---|---|
| `<cid>.olb.xml` | `staging/<cid>/` | Capture 的 `XMATIC_XML2OLB` |
| `<封装>.il` | 封装库目录 | Allegro `load()` |
| `<封装>.step` | 封装库目录（在 `steppath` 里） | 3D |
| `<封装>.map.xml` / `.3dmap.xml` | 封装库目录（在 `step_mapping_path` 里） | 3D 映射两种机制 |
| `README.txt` | `staging/<cid>/` | 人读小抄（含手工方式） |

单点失败不阻塞主体：3D 下载失败只记 `warnings`，符号/封装照常出。

### 3.11 预览渲染 `lcsc2cadence/render/`

把解析出的几何画成 SVG。坐标约定：**符号**解析时已 Y 翻转（上为正），SVG 里再取反；
**封装**解析后 Y 与 SVG 同向，不翻转。viewBox 由所有图元的外接框决定。
颜色沿用 EAGLE/KiCad 风格（深红外形、深蓝引脚、橙丝印、金焊盘），通孔焊盘画白色钻孔圈，
pin-1 加红圈标记。

## 6. 关键技术风险与验证计划

按「杀掉项目」的概率排序：

**R1 OLB XML schema（最高）**。未公开。**缓解**：schema 自发现（3.3），用你手建的参考元件回读真 schema，不猜。**验证**：跑 `learn-schema`，看能否正则回读出你参考元件的引脚。

**R2 XMATIC 在 17.2/17.4 上是否存在（高）**。**验证**：`probe` 命令敲两条命令看回显。若 17.2 没有，符号在该版本退化为方框——需你决定是否接受。

**R3 封装几何映射（高）**。多层焊盘合并、异形焊盘、曲线逼近、内孔限制。**验证**：拿 3 个典型封装（0603 电阻、QFN、带内孔的焊盘）跑，人工比对 `.dra`。

**R4 3D 位置校准（中）**。无官方约定。**验证**：同一元件用两种口径各出一版，在 3D Canvas 里看哪个贴合，定下默认。

**R5 上游端点数变（中）**。EasyEDA 与商城的端点都是免鉴权非官方端点。**缓解**：端点集中在
`catalog/api.py` 顶部常量；失败时报「上游可能已变更」并带上是哪个端点。**验证**：
2026-10-16 四个商城端点 + 两个 EasyEDA 取数端点实测可用。

**R6 许可（低但致命）**。**验证**：落地前逐个核 LICENSE。

**R7 累积工程库的合并正确性（中）**。`.olb` 二进制不能直接改，只能
`OLB2XML → 合并 XML → XML2OLB`。合并模块**故意不用 XML 解析器**（真 schema 未公开，节点树解析
容易被未知命名空间搞崩），只做保守的「把 `<Part>` 插到根结束标签之前 + 同名先删」。
**验证**：`tests/test_olb_merge.py` 覆盖新建、追加、同名替换、无 Part 的容错；真机上再用
两个元件各放一次，回读工程库看是否 2 个 Part。

**R8 放置体验（低）**。跟随光标依赖交互放置命令；都没有则退回固定坐标（元件会落在
配置的坐标上）。TCL 用 `exec` 调 exe 合并库，Windows 上可能闪一下控制台 —— 已在
验证记录里列为待观察项。

## 7. exe 构建与部署

- **本工具的开发环境无法替你编译 exe**：没有 Windows 工具链，PyInstaller 也不能跨平台产出
  Windows exe。构建必须在**你本机**跑 —— 这也正好方便你边构建边验证。
- **给你一键构建**：双击 `build_exe.bat`（它调用 `build_exe.ps1`）—— 在装了 Python 3.9+ 的
  Windows 上跑，产出 `dist\lcsc2cadence.exe`（单文件）。脚本分六步并在每一步打印进度：
  找 Python（识别并跳过 Microsoft Store 的占位程序）→ **镜像源码到
  `%USERPROFILE%\lcsc2cadence-build`** → 建 `.venv` → 装依赖 → 跑 158 个离线测试 →
  PyInstaller 打包 → **真跑一次 exe 的 `selftest`**。
  全程用 `Start-Transcript` 记到 **`build_log.txt`**，失败时窗口直接给出原因与日志路径。

  **为什么必须先镜像到别的目录再构建**：工程目录在 `AppData` 深处，这类路径被杀毒软件实时扫描、
  也被桌面应用的文件监视器盯着；PyInstaller 的 analysis 阶段要对几万个文件做 stat/open，
  在那儿会慢到像卡死（实测：普通目录 10 秒跑完，那儿 10 分钟零进展）。镜像失败会自动退回原目录。

  **打包阶段有心跳 + 看门狗**：每 10 秒打印「已用时间 / 静默时长 / PyInstaller 最近一行」；
  连续 10 分钟零输出即判定卡死，自动杀掉子进程并判构建失败（不无限等）。
  子进程带 `PYTHONUNBUFFERED=1`，且 stdout **和 stderr 都**纳入进度判断
  —— PyInstaller 的日志其实走 stderr，只看 stdout 会得到一条空白心跳。
- **打包入口必须是 `entry.py`，不能是 `src/lcsc2cadence/__main__.py`**。PyInstaller 把入口当
  独立顶层脚本编译，包上下文会丢失，`__main__.py` 里的相对导入必然 `ImportError`。
  `entry.py` 用绝对导入 + spec 里的 `pathex=["src"]`；包内 `__main__.py` 仅供
  `python -m lcsc2cadence`。`tests/test_entrypoint.py` 钉住这条。
- **「打包成功」≠「exe 能用」**：构建脚本最后调用 `lcsc2cadence selftest`（八项离线检查：
  网页资源 / TCL 模板 / 目录可写 / 解析器 / 符号 XML / 封装 SKILL / SVG 渲染 / HTTP 服务），
  不通过即判定构建失败。自检逻辑写在 Python 里而不是 PowerShell 里，避免 PS 5.1 的引号坑。
- 打包必须把**网页界面**打进去：`lcsc2cadence.spec` 的 `datas` 已包含
  `server/web/*.html|css|js`（含 `three.min.js`）、`install/templates/*.tcl`，
  以及给 selftest 用的 `tests/data/C2040.json`。
- `spec` 的 `excludes` 里排掉了 `cryptography / OpenSSL / pyopenssl / bcrypt / cffi`：
  这是 `requests → urllib3.contrib.pyopenssl` 的**可选**加密后端，我们只用 stdlib 的 `ssl`，
  但它的 rust 动态库有 4 MB+、上千个文件。排掉后产物从 13.3 MB 降到 8.3 MB，HTTPS 取数不受影响。
- 首次使用：`lcsc2cadence.exe deploy` 自动把插件装进 Cadence 并配好 Allegro env；
  安装包（Inno Setup）可静默完成同样的事。

> 脚本的编码/行尾约定（踩过坑，别改）：`build_exe.bat` 必须是 **ASCII + CRLF**；
> `build_exe.ps1` 必须是 **UTF-8 with BOM + CRLF** —— Windows PowerShell 5.1 在没有 BOM 时
> 按 ANSI 读文件，中文会乱码，带括号的块还可能在解析时出错。
