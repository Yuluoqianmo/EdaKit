## 运行链路

```text
Capture → EdaKit 菜单 → 原生 CEF 右侧停靠面板
                         ↓ /embed（HTML/CSS/JS）
                  本机 edakit.exe HTTP 服务
                   ↙                    ↘
          商城查询 / CAD数据 / PNG      文件放置队列
                                         ↓
                          Capture 内 Tcl 轮询与 OLB 规范化
                                         ↓
                         激活最近原理图 → PlaceNew → 单击落位
```

## 宿主与生命周期

`src/edakit/install/templates/edakit.tcl` 的 openMall 为正式入口：ensureServer → openCefMall。使用 Cadence 自带 orPrmWebComp、CreateControlBar、WF_CEF、LoadResource 和 ShowWidget。

同一地址和有效句柄：只 ShowWidget，保留页面状态。地址变化：LoadResource 后显示。宿主 API 报错：清理旧句柄并重建；销毁失败时保留所有权并停止重复创建。CEF 调用失败回退 OpenURL；无 API 异常的白屏由用户选择 Legacy Viewer 回退。不同宿主的网页状态相互独立。服务重启或面板销毁后不承诺恢复页面状态。

不使用独立试验 Tcl 作为业务依赖，不修改 Capture 全局安全设置。主菜单自动启动单文件 exe，本地服务地址由运行目录 url.txt 动态读取。

## 页面与性能边界

唯一正式页面在 `server/web/embed.*`；当前保留 ES3 风格、JSONP 和 PNG，兼容 Chrome 45 及旧入口。CEF 接入不等于现代浏览器能力升级：探针 WebGL1/2 均未获得上下文，3D继续用真实 OBJ 的服务端 CPU 渲染。

已实施：同器件详情加载去重、连接轮询单请求、重复菜单不刷新、查询禁重、令牌防迟到响应覆盖、图片等待与超时。3D旋转提示为“正在生成3D视角预览”；该文案不表示每次远端下载。后续优化需分别测量网络、模型解析、PNG渲染和页面显示耗时，再决定缓存或调度改造。

## 数据与放置

商品查询、属性与封装选项由 catalog/ 负责，原始查询 ID/key/value 保持，glossary 仅处理显示。CAD由 fetch/easyeda 解析；二维由 render/ 输出 PNG；3D由 threed/ 输出角度预览。

网页只提交放置请求，不直接执行 Capture 原生命令。bridge/ 与 pipeline.py 生成中间文件，Tcl每400ms轮询，保留既有 OLB 合并、回读和规范化。PlaceNew 调用返回仅表示命令已执行，不代表用户已落位。原理图焦点、引脚和Esc是每次改放置流程的回归门槛。
