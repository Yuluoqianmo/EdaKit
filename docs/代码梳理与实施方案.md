# 代码梳理与实施方案

日期：2026-10-20。范围：一级菜单、EdaKit 改名、跟随光标。封装生成不在本轮开发范围。

## 数据与调用链

商城 catalog.MallClient / Fetcher → easyeda.parse_component → Component(Symbol/Footprint/Model3D) → render SVG / HTTP 详情 → pipeline.stage_component → PlaceRequest.submit → req_*.req → Tcl handleOne → buildOlb → writeOlb / normalizeOlb / 回读核对 → placePart → resp_*.resp。

Python 用 requests 和标准库 HTTP 服务，运行于 Capture 外。Capture Tcl 在进程内操作原理图，每 400ms 轮询 key=value 队列；前端分现代 JS 与 IE7 ES3/JSONP。符号生成使用实际 Capture 17.2 XML 方言，库转换需 Capture 的 XMATIC 扩展。构建链是 entry.py → edakit.spec → PyInstaller 单文件 exe，deploy 解包内模板。

CLI 的 stage/build 是离线导出路径，mall/serve 是交互路径，place 是队列入口，probe/selftest 是诊断路径。install 负责安装根探测、模板部署；winfocus 仅改善外挂商城切前台体验。symbol/tcl.py 仍提供单次导出脚本，运行插件主路径是 install/templates/edakit.tcl。

## 原实现中与本轮有关的问题

1. Config 默认 cursor，Tcl 却强制 followCursor=0，界面仍声称光标放置；成功回执与真实行为不一致。
2. Place Part 面板会触发引脚散乱，旧交互路径不适合直接恢复。交接记录把原因归于面板实例化，但“数据侧无法修复”是此前实验结论，不是已获 Cadence 官方确认的根因。
3. pendingPlace 只保存库/零件/封装，丢失放置方式、坐标、请求序号；错误判断写法有误，最终失败不会更新原 ready 回执。
4. 菜单仅使用 AddAccessoryMenu，出现在 Accessories 下。
5. 名称分散在包、命令、模板、环境变量、资源路径、打包、安装器和测试中；不能只换网页标题。
6. README 的 schema 待校准、面板放置、测试数量与后续真机记录不一致。

### 跟随光标

- 本机官方 `D:/Cadence/SPB_17.2/tools/capture/tclscripts/OrCAD_Capture_TclTk_Extensions.pdf` 第 141 页列出 PlacePartEx 的四参数及属性扩展签名。在线 Cadence 文档副本：
  https://www.ema-eda.com/wp-content/uploads/files/resources/files/OrCAD_Capture_TclTk_Extensions.pdf
- GitHub 作者记录 PlacePartEx 在 23.1 中为交互放置（作者一手实验，不能直接证明 17.2 行为）：
  https://github.com/redstone39/orcad-capture-toolkit/blob/main/references/api-reference.md
- 本机 17.2 官方 `capPSpiceModelApp/tcl/PSpiceModelAppCapture.tcl` 第 123 行起，使用 `PlaceNew $olbPath $symbol $flag`，上层传 flag=0。这是另一个原生放置入口。
- GitHub 实际 Tcl 示例展示 GetSelectedObjects / SelectObject 用法，可作为直接放置后选择对象的备选研究依据：
  https://github.com/z-Wind/OrcadTcl/blob/master/replaceGlobalPower.tcl
- Cadence 官方社区建议 PlacePart 后用 SelectObject，但这本身不能证明可以进入鼠标移动状态：
  https://community.cadence.com/cadence_technology_forums/pcb-design/f/allegro-x-scripting-tcl/65616/how-can-parts-be-placed-programmatically-and-then-modified-afterwards/1407401

决策：先采用无需临时落位/选择/剪贴板的原生交互入口。优先 PlacePartEx；仅命令不存在时使用 PlaceNew；执行报错后不重试另一种放置，避免重复实例。未采用 Move x y bool：官方签名是坐标移动，不足以推断其会启动光标跟随。未采用外部按键注入。

验证边界：本轮只能离线验证命令选择、参数、失败处理、延迟回执和语法；17.2 原生光标状态、引脚几何、取消行为必须真机确认。调用接受后回执 armed，不称为已落位。

### 改名

用户选定 EdaKit / EDA 工具箱。项目目录、Python 包、exe、spec、入口、Tcl 文件/命名空间、环境变量 EDAKIT_EXE、网页与安装器统一。新数据目录 edakit；旧配置首次迁移，绝对库路径保留。旧队列/心跳/端口/可执行路径不迁移。

安装器 AppId 保留以识别升级。Allegro env 标记和备份名保留，防止重复环境配置块；Allegro SKILL 生成器代码保持原样。
