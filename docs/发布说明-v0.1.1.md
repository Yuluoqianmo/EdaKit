# EdaKit v0.1.1

审核修复版。用户已确认 0.1.1rc1 手动测试功能正常；正式版仅调整版本标识并重新构建。

## 更新

- 本地服务保持绑定127.0.0.1，增加Host、Origin、Referer与跨站请求校验；每次启动生成随机访问凭证，动态页面和接口要求授权。放置改为POST，写请求要求application/json。
- JSONP回调名称限制格式和长度，响应增加nosniff与no-referrer；禁止通过HTTP修改schema_profile；服务诊断日志隐藏访问凭证。
- 修复Tcl脚本括号与属性列表转义，使用list/lappend构建属性，特殊字符不再改变属性值或成为命令。
- 校验元件/模型路径标识；STEP下载限制大小并验证完整性，模型及映射原子写入，失败时保留原文件。
- 404等确定性错误不重试，临时错误指数退避；配置读取按文件状态缓存。
- 自动生成的放置回执保留30天，清理后仍拒绝旧时间ID重放；自定义ID继续保留永久回执。
- 固定运行及构建依赖，补充Windows原生/Tcl测试环境标记、Windows/Linux CI和专项静态检查。
- 将完整发布代码与审核修复同步到默认分支main，修正此前首页文档与默认分支源码不一致的问题。

## 安装与验证

保存工程并退出全部Capture、Allegro，下载 `EdaKit-0.1.1-Setup.exe`，覆盖到原EdaKit安装位置并沿用Cadence根目录；安装后重新打开Cadence菜单入口。不要复用旧的本地服务地址或书签。

- 用户手动验收正常；本地全量回归 **674 passed / 2 skipped**，专项静态检查通过，冻结程序自检通过。
- 隔离目录验证初始化、安装、重复安装、卸载和保留用户文件；打包服务的鉴权验证通过。
- 工作台页面切换、商城查询、POST放置及JSONP兼容调用已用本机Edge/Playwright验证，无脚本运行错误。
- Linux自动化验证以GitHub Actions实际结果为准，本机没有Linux运行环境。

主要原生验收环境仍为Windows 64位 / Cadence17.2。旧IE缺少JSON能力时仅支持只读查询，安全放置请使用CEF工作台。既有iBOM板厚/铜层/过孔/槽孔等边界见使用文档。

Release附件：安装包、SHA256SUMS.txt和release-sha256.json。源码、测试、依赖锁文件和文档入Git；本机二进制、构建缓存、用户库/配置和验收输出不入Git。
