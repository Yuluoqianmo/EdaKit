# 后台运行与放置提示优化

2026-10-21。用户确认打开商城和放置时出现的是黑色命令行窗口。

## 原因与修改

此前单文件exe使用控制台子系统。Capture打开商城会启动 `edakit.exe serve`，放置合并库时又调用 `edakit.exe olb-merge`，两处均可能创建黑窗。CEF并不要求这些窗口。

本次将主程序 `edakit.exe` 构建为Windows GUI子系统，进程启动时不分配控制台。它继续承担原来的服务和库合并命令，Tcl、队列、OLB规范化和PlaceNew流程不改。不是启动黑窗后再隐藏。

新增同目录 `edakit-cli.exe`，使用控制台子系统，保留显式命令行输出和诊断。命令行版deploy仍将exe_path.txt记录到同目录的无控制台版，避免后续安装重新引入黑窗。打包脚本同步交付两份exe。

无控制台版stdout/stderr写入 `%LOCALAPPDATA%\edakit\background.log`；非预期异常写入堆栈并以非零状态退出。原生菜单和放置日志仍在 `edakit.log`。失败不会被当作成功，页面仍显示错误。

页面放置过程不再轮番提示“已提交”“数据已准备好”；保持准备提示，只有需要用户动作时提示“请点击原理图，继续放置”，命令armed后提示“单击原理图落位，Esc退出”。这些文本不宣称用户已经单击落位。未删除必要的准备步骤，也不宣称准备耗时已降低。

## 真机步骤

无需重新deploy或重启Capture。主exe替换后，菜单会启动新版服务；若仍有旧工作台页，点击菜单让它加载新服务地址。

1. 点击 **EdaKit → LCSC Mall**。预期直接在右侧加载商城，没有黑色控制台窗口。
2. 搜索并选择一个已有成功放置记录的0603电阻，等待详情加载，点击放置。预期只有页面内的准备提示，不出现黑窗，不出现“已提交/准备完成”轮番状态。
3. 点击原理图，确认器件跟随光标，单击落位，引脚正常，Esc退出；测试工程可不保存。
4. 换一个器件重复两次，检查焦点、菜单复用和原放置功能。首次准备仍可能耗时，本轮没有优化合并/渲染速度。
5. 若失败，反馈停止步骤、C编号、是否出现黑窗，以及下方日志。不要重复点击制造多份请求。

```powershell
Get-Content "$env:LOCALAPPDATA\edakit\edakit.log" -Tail 80
Get-Content "$env:LOCALAPPDATA\edakit\background.log" -Tail 80
```

手动诊断现在使用：

```powershell
& 'E:\outputs\edakit\dist\edakit-cli.exe' selftest
& 'E:\outputs\edakit\dist\edakit-cli.exe' status
```

主动运行CLI出现控制台属于预期；Capture正常入口只调用无控制台版。以后需要部署时使用CLI可查看输出，但必须将两份exe放在同目录。
