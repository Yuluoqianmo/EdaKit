# 电容符号与连续放置修复

日期：2026-10-21。用户后续已反馈“功能测试没问题了”。本文保留该轮实施、散列和验收清单；最新字体与按钮样式更新、当前安装包散列以[项目交接](项目交接.md)为准。

## 问题与修复

1. 电容的两条极板使用 PL 折线，原 Capture XML 转换器没有输出这些图元。现将折线转换为 Line，并补充闭合多边形及圆/椭圆的输出。三个实际电容样本均生成两条完整极板。
2. C170151、C19110 的源 CAD 将两端引脚标成输入类型，Capture 会画出方向箭头。两端 R/C/L 符号统一输出为 Passive；IC 等其他器件的电气类型保留。
3. 固定 lcsc_test.olb 被覆盖后，Capture 仍可能使用该路径第一次加载的内容，导致后续器件 PlaceNew 返回 0。现在每个内容指纹使用独立、稳定且文件名也不同的 OLB：`olb_cache/<digest>/ek_<digest前24位>.olb`。lcsc_test.olb 仅作为规范化中间文件，不再交给 PlaceNew。缓存不可用或旧请求没有指纹时，使用唯一临时快照路径。
4. PlaceNew 只有返回 1 才报告启动成功；返回 0 写入失败响应，避免界面误报。即使返回 1，仍仅表示宿主接受启动命令，不代表用户已经落位。

重复放置、A→B→A、重启后的缓存复用继续保留，命中时跳过 XML/OLB 转换及工程库合并。旧版缓存因缺少新文件或元数据版本不符而重建。缓存保留最多 128 项，清理为尽力执行；Capture 占用的文件可能暂时无法删除。

两端 R/C/L 使用 `_G2` 内部符号名，使新放置绕过原理图中已经缓存的旧定义。内部名仍限制为 31 字节，Value 保留原型号。已有原理图上的旧器件不会自动修改。独立库路径可能增加 Place Part 对话框中的库条目；不再承诺只保留一个固定库入口。

## Capture 真机验收

1. 保存工程，退出全部 Capture 后重新打开。主程序与 Tcl 已同步部署，无需手工再 deploy。打开测试原理图页，再从 EdaKit → LCSC Mall 打开商城。
2. 搜索 C23630，点击放置；如显示等待原理图，切回原理图页。确认电容跟随光标，两条极板完整、没有方向箭头，单击落位，Esc 结束本次放置。
3. 分别搜索并放置 C170151、C19110，每次都先检查光标跟随与型号，单击落位后 Esc。后两种也应正常出现，不能沿用第一种符号。
4. 返回 C23630 再次放置，检查型号、Value、引脚及符号正确。日志应出现 OLB cache HIT；首次使用或旧缓存失效时允许 MISS。第一次因刷新窗口而等待，不作为缓存失效证据，按日志判断。
5. 再选择一种 IC（例如 C2040）和超长型号 C5123614，确认可跟随、落位、Esc，IC 引脚没有被统一改成 Passive。
6. 保存测试结果，关闭并重开 Capture，再放置已测试器件，检查能否复用和正常启动。若使用双 Capture，补查各自定向放置；最后关闭全部实例后确认后台正常退出。

验收针对本次新放置的器件；不要用此前已放置的旧电容判断新符号是否生效。实际提速幅度、长期稳定性和以上原生 Capture 操作尚未宣称通过。

反馈建议：C 编号、第一次/重复/切换后的操作顺序、是否跟随、是否正确落位、符号与 Value 是否一致。失败时提供 Diagnostics 日志末尾的 OLB cache、cursor CALL/RETURN 与 queue stage 行；同时说明当前哪个原理图页处于激活状态。
