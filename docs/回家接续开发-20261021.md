## 拉取和准备环境

已有克隆目录时先保存本地修改，再执行：

```powershell
git fetch origin
git switch feat/pcb-footprint-acceptance-20261021
git pull --ff-only
```

首次获取：

```powershell
git clone --branch feat/pcb-footprint-acceptance-20261021 https://github.com/Yuluoqianmo/EdaKit.git
Set-Location EdaKit
```

使用有该私有仓库权限的 GitHub 账号。以下命令在仓库根目录执行，Python 3.10+，Windows/Cadence 17.2 为本轮目标环境：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
# 将下面 Cadence 路径替换为家中实际安装路径
$env:PATH = 'D:\Cadence\SPB_17.2\tools\bin;' + $env:PATH
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
```

没有 Cadence tclsh 的机器只能执行 Python 侧验证；Tcl 与原生验收需要安装环境。部分旧 Tcl 测试依赖可发现的 tclsh；不要把环境缺失当成原生成功。

## 在家重新准备测试目录

仓库里的 `samples/acceptance-20261021` 保存已验证的独立测试库、PCB 原生文件、截图和 SHA256 清单，可供核对。生成脚本需要按本机路径重建；已留存 OLB 内的历史绝对路径作为证据保留，不依赖旧电脑存在这些目录。

```powershell
$taskRoot = Join-Path $env:USERPROFILE 'edakit-work-20261021'
New-Item -ItemType Directory -Path $taskRoot -Force
$nativeRoot = Join-Path $taskRoot 'native-r3'
$captureRoot = Join-Path $taskRoot 'capture-p5r2'
.\.venv\Scripts\python.exe tools/diag/prepare_native_footprint.py $nativeRoot
.\.venv\Scripts\python.exe tools/diag/prepare_capture_acceptance.py $captureRoot
```

两个生成器要求目标子目录不存在。再次测试时换新的子目录，避免覆盖失败现场或已加载的库。生成 Capture 脚本默认零件为 RP2040_P5R2，PCB Footprint=C2040_QFN56_EP。

在 Allegro 的 Setup → User Preferences → Paths → Library，将 `$nativeRoot/C2040` 的实际路径加入 psmpath 和 padpath，保留原路径。可从仓库验收样本复制 `.dra/.psm/.pad` 到该目录使用，或新建 Package Symbol（完整路径 `$nativeRoot/C2040/C2040_QFN56_EP.dra`）并在 Allegro 命令栏执行该目录的 `manual_build.il`。不要在部分生成的图纸重复加载。

在 Capture 中打开独立原理图测试工程。将下面路径替换为 `$captureRoot` 的实际路径，Tcl 使用正斜杠：

```tcl
source "C:/Users/你的用户名/edakit-work-20261021/capture-p5r2/build_library.tcl"
```

预期 EDAKIT_NORMALIZED_LIBRARY_READY。脚本完成输入 XML→中间 OLB→规范化 XML→最终 OLB→最终回读。此时不要打开 Place Part 面板。激活原理图页，在命令窗口执行：

```tcl
source "C:/Users/你的用户名/edakit-work-20261021/capture-p5r2/place_native.tcl"
```

预期 EDAKIT_NATIVE_ARMED，移动鼠标到原理图点击落位，Esc 退出。该脚本使用现有插件已验证的激活原理图、UnSelectAll、ZoomRedraw、PlaceNew 顺序，每次使用新库路径快照避免路径缓存。

## 下一项验收（从这里继续）

1. 在独立测试工程放置 U1，确认引脚显示正常、PCB Footprint=C2040_QFN56_EP。
2. 开启格点吸附，从物理引脚 1、57 拉导线，分别加 TEST_PIN1、TEST_EP57。确认连接点能准确吸附。
3. Capture 选中 .dsn，Tools → Create Netlist → PCB Editor，启用 Create PCB Editor Netlist；输出到本机测试目录的 allegro 子目录。
4. 启用 Create or Update PCB Editor Board（Netrev），新建板 Input Board 留空，Output Board 使用本机测试目录的 C2040_IMPORT.brd；选择打开 Allegro PCB Editor。
5. 若报错，保留第一条错误及上下文；若成功，Place → Manually 放置 U1，核对 57 个引脚与 TEST_PIN1/TEST_EP57 网络归属，保存并重新打开。

源 C2040 把 IOVDD/DVDD/GND 等标为 bidirectional。本轮对重复的非 Power 名称加序号，未依据名称改成 Power；若后续改电气类型，需有数据手册或明确用户输入支持。物理编号始终保持不变。

通过后再做正式 Capture/PCB 统一安全命名（目前 C2040_QFN56_EP 仅为隔离测试别名）、插件入口与重新打包部署。详细路线见 PCB封装生成方案.md。
